# NRF24 多节点物联网络实验平台 — 课题支撑说明

## 平台概述

本课题基于 **ESP32-S3 + NRF24L01+** 构建了一套 **多节点无线物联网络实验验证平台**，包含嵌入式固件、PC 上位机 GUI、可控干扰源三大组成部分，支持 **ALOHA (GFRA) 和 CSMA (GBRA) 两类随机接入机制的实时切换与参数动态配置**，可为一套完整的 VoI 驱动的混合随机接入机制适配方法研究提供实验验证支撑。

### 通信架构

```
TX 节点 ──(NRF24 2.4GHz)──▶ RX 节点 ──(UART)──▶ PC GUI
   │                           │
   └──(UART/TCP)──▶ ── ── ── ─┘
       控制命令通道           统计上报通道

每个 TX 节点:
  - 无线侧: NRF24 发送数据帧到 RX (带序列号 + CRC)
  - 有线侧: UART 或 WiFi TCP 接收 PC 的控制命令 (MAC/SLOT/BURST)

RX 节点:
  - 无线侧: NRF24 接收所有 TX 的数据帧
  - 有线侧: UART 上报逐帧统计 (丢包/重复/乱序/CRC错误)

Jammer (干扰源):
  - 无线侧: NRF24 持续发送满载帧，占用空口
  - 有线侧: UART/TCP 接收 PC 的 JAM ON/OFF 命令
```

## 课题研究内容与平台支撑对照

### 研究内容 (1)：面向缓存队列数据的 VoI 整体度量函数

> 突破传统模型中单包 VoI 度量局限，研究面向缓存队列数据的 VoI 整体度量函数，量化数据传输量对系统任务的边际价值增益。

**平台支撑：**

- **帧级序列号追踪**：每帧携带 16 位序列号（`app_proto_frame_t.seq`），接收端可检测丢包（`seq_gap`）、重复（`seq_dup`）、乱序（`seq_out_of_order`），为构建"信息年龄（AoI）/ 信息价值（VoI）"度量提供了精确的单帧时间戳与连续性记录。
- **时隙级细粒度统计**：TX 端每个时隙输出 `GUI_STAT: slot=<n> attempted=<0|1> success=<0|1> reason=<code>` 日志，记录每次发送尝试的完整结果（成功 / 信道忙退避 / 概率拒绝 / 超时失败），为缓存队列的发送-成功动态建模提供了逐时隙的状态观测数据。
- **批量发送（Burst）原语**：支援 `BURST <count> <interval_ms> <payload>` 命令，可精确控制发送速率与数据量，配合可配置的 `slot_limit`（时隙上限），可模拟不同缓存压力下的数据注入场景，量化不同数据传输量对任务完成度的边际价值。
- **硬件随机数驱动的概率退避**：使用 ESP32 硬件真随机数发生器（`esp_random()`）生成 MAC 概率门限，确保实验数据的统计无偏性，避免软件 PRNG 可能引入的人为相关性。

### 研究内容 (2)：跨 MAC 及 RRC 的统一分析框架 (GFRA/GBRA)

> 扩展研究内容（1）的模型，形成跨 MAC 及 RRC 分析模型，实现 GFRA/GBRA 理论分析框架的统一。

**平台支撑：**

- **双 MAC 协议运行时共存**：固件原生实现 ALOHA（Grant-Free Random Access, GFRA）和 CSMA（Grant-Based Random Access, GBRA）两类随机接入机制，共享同一套时隙调度引擎和统计框架：
  - **ALOHA (GFRA)**：纯概率门控——每时隙以概率 q% 独立决定是否发送，无中心调度，对应 GFRA 的"先发后听"范式。
  - **CSMA (GBRA)**：先侦听后发送——通过 NRF24 RPD（接收功率检测，-64dBm 阈值）感知信道占用，忙时进入退避窗口（`csma_window_slots` 个时隙），对应 GBRA 的"先听后发"范式。
- **统一的 MAC 门控接口**（`app_tx_gate_decide()`）：两种 MAC 协议的准入决策共用同一函数，输出统一的决策枚举（`ALLOW / BUSY / BACKOFF / PROB_REJECT`），天然构成跨 MAC 的统一分析框架。
- **运行时无感切换**：通过 UART/TCP 命令 `MAC ALOHA|CSMA <q%>` 可在不重启设备的情况下切换 MAC 协议，无需重新编译或烧录固件，支持同一硬件在同一实验场景中的 A/B 对比验证。
- **统一参数空间**：`slot_ms`（时隙长度）、`q_percent`（发送概率）、`csma_window_slots`（退避窗口）构成统一的 MAC 参数向量，可作为跨 GFRA/GBRA 理论分析的优化变量。

### 研究内容 (3)：稳态场景下的 VoI 优化理论推导

> 考虑稳态系统场景，采用最优化理论，推导面向 VoI 的 GFRA/GBRA 机制适配与参数优化解析结果。

**平台支撑：**

- **可控的稳态实验条件**：
  - **固定间隔发送**：`BURST` 命令 + `interval_ms` 参数可生成恒定速率的数据流，建立稳态负载。
  - **可配置时隙参数**：`SLOT <ms> <csma_window>` 命令精确控制时隙粒度（默认 2ms，可调至 μs 等效精度），满足不同时间尺度下的稳态建模需求。
  - **概率门限 q 精确可调**（0-100%）：可在全负载（q=100%）与低负载（q<100%）之间精细扫描，验证最优 q 值的理论推导结果。
- **完整统计闭环**：TX 端追踪 `frame_sent / tx_ok / tx_fail / retries_sum / retries_max`，RX 端追踪 `rx_packets / frame_ok / crc_fail / seq_gap / seq_dup / seq_out_of_order`，从发送到接收形成完整的端到端性能观测向量，可直接代入优化目标函数进行数值验证。
- **GUI 统计面板实时可视化**：如项目实验时配合 PC GUI 界面截图，可直观展示不同参数设定下的成功率和重传统计对比。

### 研究内容 (4)：动态场景下的低复杂度 VoI 驱动机制适配

> 考虑动态系统场景，设计面向低复杂度的 VoI 驱动 GFRA/GBRA 机制适配与参数优化技术，验证其与理论性能边界的匹配度，形成 VoI 驱动的混合随机接入场景通用机制选择方法体系。

**平台支撑：**

- **动态场景模拟—可控干扰源（Jammer）**：
  - 独立高优先级任务（`nrf24_jam`，优先级 10），持续发送全满载（32 字节）干扰帧，空口占空比接近 100%。
  - 通过 `JAM ON / JAM OFF` 命令随时启停（GUI 一键控制），模拟突发性外部干扰或竞争设备加入/退出场景，用于验证动态信道条件下的机制切换策略。
  - Jammer 不影响正常 TX burst 的 MAC 门控和统计功能，可在干扰存在下观测 CSMA vs ALOHA 的性能差异。
- **运行时参数在线调整**：所有 MAC 参数（协议模式、q 值、时隙、退避窗口）均可在运行时通过串口或 WiFi TCP 远程修改，无需重启设备，可直接验证"检测到信道变化 → 在线调整 MAC 参数"的自适应策略。
- **WiFi 无线控制通道**：ESP32 创建 SoftAP 热点 + TCP Server（端口 3333），PC 可通过 WiFi 无线连接并发送控制指令，避免了有线连接对实验环境的物理干扰，也更接近真实物联网络的部署场景。
- **多 TX 节点并行实验**：PC GUI 支持动态添加/删除多个 TX 发送端（每个对应一块独立的 ESP32+NRF24），可在同一 GUI 中并行控制多个竞争节点，模拟多用户竞争接入场景，验证多节点下的机制适配方法。
- **低复杂度适配验证**：时隙参数、概率门限均为纯整数运算，MAC 门控决策路径极短（一次 RPD 读取 + 一次随机数比较），固件实现本身就是"低复杂度在线适配技术"的参考基线，可直接测量适配算法的计算开销（时隙利用率、CPU 占用）。

## 技术参数

| 参数 | 配置 |
|------|------|
| 空中速率 | 250Kbps / 1Mbps / 2Mbps 可配 |
| 单帧载荷 | 最大 32 字节（22 字节用户数据 + 8 字节帧头 + 2 字节 CRC） |
| 数据包空中时间 | ~1.33ms @ 250Kbps（含前导码+地址+载荷+CRC） |
| TX+ACK 完整周期 | ~1.77ms |
| 默认时隙 | 2ms（对齐 TX+ACK 周期） |
| RPD 检测阈值 | -64dBm |
| CSMA 侦听窗口 | 1500μs（覆盖完整数据包） |
| 自动重发 | 最多 10 次，间隔 ~1000μs |
| 控制接口 | UART (115200bps) + WiFi TCP (端口 3333) |

## 总结

该平台以 **真实的硬件节点 + 可控的实验参数 + 完整的统计观测 + 动态的场景注入**，构建了一套面向"VoI 驱动的混合随机接入机制研究"的端到端实验验证环境。从单包级 VoI 度量的数据采集，到跨 GFRA/GBRA 统一分析框架的固件实现，再到稳态优化理论的实验标定和动态适配策略的在线验证，四个层面的研究内容均可在此平台上获得实物实验数据的支撑，从而将理论分析与实际物联网络行为建立直接对应关系。
